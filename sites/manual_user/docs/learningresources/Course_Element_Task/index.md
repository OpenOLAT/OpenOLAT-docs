# Course Element "Task" {: #course_element_task}

## Profile {: #profile}

Name | Task
---------|----------
Icon | :o_icon_o_gta_icon:
Available since | New edition with release 19
Functional group | Assessment
Purpose | Modeling of complex task workflows with configurable substeps such as submission of solution documents, feedback and revision loop, provision of sample solution and assessment
Assessable | yes
Specialty / Note | also available as [group task](../Course_Element_Grouptask.md)


With the course element "Task" you organize file submissions and submission assignments in your course. Participants upload their solution to the course and receive feedback and an assessment. [Peer reviews](../../../manual_how-to/peer_review/peer_review.md) are also possible, as are revisions and sample solutions.

!!! note "Note"

    The functionality and structure of the course elements "Task" and "[Group task](../Course_Element_Grouptask.md)" are similar.


## Workflow at a glance {: #workflow_overview}

Course owners set up the task in the course editor, participants work on it in the course, and coaches accompany and assess the submissions.

In the tab "Workflow", course owners switch on the steps the task consists of and set the deadlines if needed. In the order of the user interface, these are:

1. **Task assignment**: Course owners store one or more tasks. Participants choose a task or are assigned one and download it.
2. **Submission**: Participants submit their solution, depending on the setting by a submission deadline.
3. **Feedback**: Coaches give feedback on the submission. Alternatively, the participants assess each other in a peer review.
4. **Revision**: If coaches request a revision, participants submit a new version.
5. **Sample solution**: Participants see the sample solution, depending on the setting only from a set date.
6. **Grading**: Coaches assess the submission, depending on the configuration with points or "Passed", and add a comment and assessment documents if needed.

Participants see the switched-on steps one below the other in the course element. They reach the next step as soon as the previous one is completed.
